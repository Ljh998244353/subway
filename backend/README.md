# Backend

P4-I2 creates the minimal FastAPI backend skeleton for the mall visual AI digital twin project. P4-I3 adds the MySQL/Alembic migration baseline without connecting to a real MySQL service. P4-I4 adds synthetic fixture read APIs for mall, floor, and store reference data.

## Scope

Current implementation:

```text
GET /api/v1/health
GET /api/v1/malls
GET /api/v1/malls/{mallId}/floors
GET /api/v1/floors/{floorId}/stores
GET /api/v1/overview?mallId=mall_demo_001
OpenAPI schema generated by FastAPI
response envelope with data, traceId, and timestamp
sanitized error envelope for HTTP and validation errors
specific 404 error envelopes for unknown mall or floor IDs
Pytest health and contract smoke tests
SQLAlchemy Core metadata for the initial MySQL table baseline
Alembic offline migration SQL generation
```

Current non-goals:

```text
no MySQL connection yet
no Redis connection yet
no business API implementation yet
no ai-services/
no real video, real mall data, real maps, real brands, or personal trajectories
```

## Local Commands

Create the virtual environment from the repository root:

```bash
python -m venv backend/.venv
```

Install dependencies:

```bash
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

Run tests:

```bash
backend/.venv/Scripts/python.exe -m pytest backend/tests
```

Run the local API server:

```bash
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

OpenAPI is available from FastAPI at `/openapi.json` when the server is running.

Generate the initial MySQL migration SQL without connecting to a database:

```bash
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head --sql
```

The Alembic baseline imports table metadata from `backend/app/db/metadata.py`. P4-I3 does not create a real MySQL service, credentials, Docker Compose file, or production deployment.
