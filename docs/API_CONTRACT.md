## Scope

本文固化后端 `/api/v1` 契约基线，用于后续 FastAPI、OpenAPI、前后端联调和部署健康检查。P4-I1 只定义契约，不创建真实 `backend/` 工程、不连接 MySQL、不接真实视频或真实商场数据。

## Global Rules

```text
base path: /api/v1
contract source after implementation: FastAPI OpenAPI generated from Pydantic models
time format: ISO 8601
internal timezone: UTC
business timezone display: frontend or API presentation layer converts explicitly
response content type: application/json; charset=utf-8
trace field: traceId
request id header: X-Request-Id, optional from client and generated by server when absent
pagination: page, pageSize, sort, order
RBAC placeholder roles: admin, operator, leasing, security, readonly
```

## Response Envelope

Successful responses must use one of these envelopes.

Single object:

```json
{
  "data": {},
  "traceId": "req_20260519093000_7f3a",
  "timestamp": "2026-05-19T01:30:00Z"
}
```

List response:

```json
{
  "data": [],
  "page": {
    "page": 1,
    "pageSize": 20,
    "total": 120,
    "hasNext": true
  },
  "traceId": "req_20260519093000_7f3a",
  "timestamp": "2026-05-19T01:30:00Z"
}
```

Error response:

```json
{
  "error": {
    "code": "STORE_NOT_FOUND",
    "message": "Store not found",
    "details": {}
  },
  "traceId": "req_20260519093000_7f3a",
  "timestamp": "2026-05-19T01:30:00Z"
}
```

## Error Codes

| HTTP | Code | Usage |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | malformed query, invalid time range, invalid filter combination |
| 401 | `UNAUTHENTICATED` | missing or invalid token after auth is enabled |
| 403 | `FORBIDDEN` | valid identity without required RBAC permission |
| 404 | `MALL_NOT_FOUND` | mall id does not exist |
| 404 | `FLOOR_NOT_FOUND` | floor id does not exist |
| 404 | `STORE_NOT_FOUND` | store id does not exist |
| 404 | `ALERT_NOT_FOUND` | alert id does not exist |
| 409 | `CONFLICTING_STATE` | status transition or idempotency conflict |
| 422 | `VALIDATION_ERROR` | schema validation failed |
| 429 | `RATE_LIMITED` | later rate-limit gate, not required in P4-I1 implementation |
| 500 | `INTERNAL_ERROR` | unexpected server error with sanitized details |
| 503 | `DEPENDENCY_UNAVAILABLE` | database, cache, or required dependency unavailable |

| Endpoint area | admin | operator | leasing | security | readonly |
| --- | --- | --- | --- | --- | --- |
| Health | read | read | read | read | read |
| Overview | read | read | read | read | read |
| Mall/floor/store reference data | read/write | read | read | read | read |
| Store analysis and ranking | read | read | read | limited read | read |
| Store alert list/detail | read/write | read/write | read | read/write | read |
| Customer profile aggregates | read | read | read | read | read |
| Heatmap and trajectory aggregates | read | read | read | read | read |
| Camera and ROI configuration | read/write | read | none | read/write | none |
| Users, roles, permissions | read/write | none | none | none | none |
| Operation logs | read | none | none | limited read | none |

RBAC is a P4/P10 implementation concern. P4-I1 only reserves permissions so later endpoint tests can assert expected `401` and `403` behavior.

## Health Check

### `GET /api/v1/health`

Purpose: backend readiness for local checks, future Compose, CI smoke tests, and deployment probes.

Auth: none in local/dev; production-like environments may require internal network restriction.

Response:

```json
{
  "data": {
    "status": "ok",
    "service": "mall-vision-backend",
    "version": "0.1.0",
    "environment": "local",
    "database": {
      "status": "not_configured",
      "dialect": "mysql",
      "migrationVersion": null
    },
    "redis": {
      "status": "not_configured"
    },
    "time": "2026-05-19T01:30:00Z"
  },
  "traceId": "req_20260519093000_7f3a",
  "timestamp": "2026-05-19T01:30:00Z"
}
```

Implementation rule: before a real database exists, `database.status` may be `not_configured`; after MySQL is required by an environment, database failure must make readiness fail with `503 DEPENDENCY_UNAVAILABLE`.

## Query Standards

Common filters:

| Parameter | Type | Rule |
| --- | --- | --- |
| `mallId` | string | stable id, never use mall name as key |
| `floorId` | string | stable id scoped to mall |
| `storeId` | string | stable id scoped to mall |
| `from` | ISO datetime | inclusive UTC instant |
| `to` | ISO datetime | exclusive UTC instant; must be greater than `from` |
| `date` | `YYYY-MM-DD` | business date, interpreted with mall timezone |
| `granularity` | enum | `minute`, `hour`, `day` |
| `page` | integer | default `1`, min `1` |
| `pageSize` | integer | default `20`, max `100` |
| `sort` | string | endpoint-specific allowlist only |
| `order` | enum | `asc`, `desc` |

Date range rule: APIs accepting both `from/to` and `date` must reject ambiguous combinations with `400 INVALID_REQUEST`.

## Endpoint Baseline

| Method | Path | Purpose | Query | RBAC |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/health` | service health and dependency readiness | none | public/internal |
| GET | `/api/v1/overview` | operations overview KPI, floor status, alerts summary | `mallId`, `date` or `from/to` | all roles read |
| GET | `/api/v1/malls` | mall list | pagination | all roles read |
| GET | `/api/v1/malls/{mallId}/floors` | floors in mall | none | all roles read |
| GET | `/api/v1/floors/{floorId}/stores` | stores on floor | `category`, `status`, pagination | all roles read |
| GET | `/api/v1/stores/{storeId}` | store detail | none | all roles read |
| GET | `/api/v1/stores/{storeId}/flow` | store flow time series | `from/to`, `granularity` | operator/leasing/readonly read |
| GET | `/api/v1/stores/{storeId}/score` | latest and historical store score | `date` or `from/to` | operator/leasing/readonly read |
| GET | `/api/v1/stores/ranking` | store ranking by score or flow | `mallId`, `floorId`, `category`, `metric`, pagination | operator/leasing/readonly read |
| GET | `/api/v1/alerts/stores` | low-efficiency store alerts | `mallId`, `floorId`, `severity`, `status`, pagination | operator/security/leasing/readonly read |
| GET | `/api/v1/alerts/stores/{alertId}` | alert detail and linked evidence summaries | none | operator/security/leasing/readonly read |
| PATCH | `/api/v1/alerts/stores/{alertId}` | update alert status or assignment | status fields | admin/operator/security |
| GET | `/api/v1/customer-profile` | anonymous aggregate customer profile | `mallId`, `floorId`, `date` or `from/to` | all roles read |
| GET | `/api/v1/heatmap` | aggregate heatmap cells | `mallId`, `floorId`, `from/to`, `granularity` | all roles read |
| GET | `/api/v1/trajectories` | anonymous aggregate trajectory flows | `mallId`, `floorId`, `from/to` | all roles read |

No endpoint may return face images, personal identity, member IDs, phone numbers, or individual-level trajectories.

## Contract Test Plan

P4-I1 is documentation-only, so executable contract tests begin in the next backend implementation increment.

Required P4 checks after backend skeleton exists:

```text
OpenAPI schema generated and committed or exported in CI artifact
GET /api/v1/health returns envelope and traceId
all documented endpoints have route stubs or explicit not-implemented tests
Pydantic validation rejects invalid dates, negative pagination, and unknown enum values
error envelope covers 400, 401, 403, 404, 409, 422, 500, 503
RBAC placeholder tests assert role-to-endpoint matrix
no API response contains face image, personal identity, member ID, phone number, or individual trajectory
```
