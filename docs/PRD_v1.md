# PRD v1 - 商业综合体视觉 AI 数字孪生运营系统

更新时间：2026-05-10

## 1. 文档定位

本文是 P0 阶段的产品需求基线，用于固定第一轮可交付范围、非目标范围、角色、核心能力、合规红线和后续设计开发的输入。本文不代表真实商场上线方案；真实上线前必须补充授权、隐私、安全、运维、数据治理和法律合规评审。

## 2. 项目目标

建设一个面向商业综合体运营场景的视觉 AI 数字孪生系统，把客流、进出店、停留、热力、动线、店铺评分和低效预警统一到可解释的运营视图中，辅助运营方进行招商、调铺、营销、安保和现场运营决策。

第一轮目标是完成可演示、可测试、可恢复的系统闭环：

```text
合成或 Mock 数据 -> 指标定义 -> 前端运营视图 -> 后端 API 草案 -> AI 事件模型草案 -> 测试与合规门禁
```

## 3. 目标用户

| 用户 | 主要诉求 | 典型动作 |
| --- | --- | --- |
| 商场运营经理 | 快速理解全场客流、拥挤、异常和趋势 | 查看总览、切换楼层、定位异常区域 |
| 招商/租赁负责人 | 判断店铺经营质量和调铺风险 | 查看店铺评分、业态对比、低效原因 |
| 楼层主管 | 发现楼层局部拥堵和低转化问题 | 查看楼层热力、进出店、停留变化 |
| 市场营销人员 | 评估活动时段客流和业态偏好 | 查看时间段趋势、客群聚合画像 |
| 安保/现场人员 | 发现拥挤、异常停留和运营风险 | 查看告警、拥挤区域、处理状态 |
| 系统管理员 | 管理账号、权限、基础配置和审计记录 | 管理角色、查看操作日志 |

## 4. 一期范围

一期按先演示、再工程化、再接入真实后端和 AI 的顺序推进。

| 模块 | 一期能力 | 说明 |
| --- | --- | --- |
| 运营总览 | 场内人数、累计客流、楼层状态、趋势、拥挤预警 | 前端 Demo 先用 Mock 数据 |
| 数字孪生 | 楼层、店铺、热力、预警、历史回放联动 | 先做 2.5D 或简化 3D |
| 店铺分析 | 进店、停留、转化、评分、排名、趋势 | 评分口径必须可解释 |
| 客群画像 | 匿名聚合的时间段、楼层、业态偏好 | 不展示个人轨迹 |
| 低效预警 | C/D 级店铺、高客流低转化、连续下滑、异常数据 | 告警规则先可配置、可测试 |
| AI 事件模型 | 摄像头、ROI、线段、进出店事件、轨迹片段、热力事件 | P0 只定义边界，不接真实视频 |
| 权限与审计 | 管理员、运营、招商、安保、只读角色草案 | 后续后端实现 |

## 5. 明确非目标

第一轮不做：

```text
真实商场上线
真实监控流接入
人脸识别或身份识别
个人级轨迹追踪展示
完整 BIM 建模
复杂招商推荐算法
多租户商业 SaaS
付费云服务或付费 API 依赖
真实品牌 Logo、商户 Logo、真实商场平面图
未授权图片、视频、字体、模型、数据集或复制代码
```

## 6. 演示版与真实上线边界

| 事项 | 演示版允许 | 真实上线要求 |
| --- | --- | --- |
| 数据来源 | Mock、合成、自绘数据 | 必须有数据处理授权和留存策略 |
| 视频素材 | 自制或合成视频 | 必须有监控、肖像、隐私和安全评审 |
| 楼层图 | 自绘几何平面 | 必须确认版权、物业授权和测绘限制 |
| 店铺名称 | 虚构店铺和通用业态 | 必须确认商标、品牌和合同授权 |
| 顾客分析 | 匿名聚合统计 | 不得默认识别身份或展示个人轨迹 |
| 部署 | 本地开发或 Docker Compose | 需要安全、备份、监控、审计和应急预案 |

## 7. 合规红线

P0 起所有后续增量必须遵守：

```text
不使用真实监控画面
不存储人脸原图
不展示个人轨迹
不使用未授权商场平面图
不使用真实品牌或商户 Logo
不使用来源不明模型、数据集、图片、视频、字体或代码
不引入付费开发工具或付费云服务
所有素材、模型、依赖必须可追溯并有许可证记录
```

## 8. 成功标准

P0 完成后应满足：

| 类别 | 标准 |
| --- | --- |
| 产品边界 | 一期范围、非目标、演示/上线边界已明确 |
| 需求可追踪 | 用户故事、指标定义、验收标准互相对应 |
| 架构可延续 | 系统设计能指导 P1-P4，不绑定付费或授权不清服务 |
| 测试可执行 | 文档检查、后续单元/API/E2E/AI 验证门禁已定义 |
| 合规可审计 | 风险、许可证审计、第三方声明已有记录机制 |
| 上下文可恢复 | `context/` 恢复包可支持下一次只输入“请进行下一步” |
