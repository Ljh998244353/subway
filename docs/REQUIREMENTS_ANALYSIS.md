# 需求分析文档

更新时间：2026-05-10

## 1. 背景与问题

商业综合体运营通常同时面对客流波动、楼层冷热不均、店铺转化差异、低效店铺识别滞后和现场异常响应慢等问题。传统报表依赖收银、巡场和人工统计，难以及时解释“哪里人多、哪里转化低、为什么预警、应该优先处理什么”。

本项目通过视觉 AI 事件、运营指标和数字孪生视图，把空间、时间、店铺和告警组织在同一套可解释系统中。

## 2. 需求分层

| 档位 | 含义 | 本项目处理方式 |
| --- | --- | --- |
| L0 合规红线 | 违反后不得继续实现 | 不使用未授权真实素材、真实监控、人脸原图、个人轨迹、付费服务 |
| L1 核心闭环 | 一期必须支撑演示和验收 | 运营总览、店铺分析、低效预警、指标定义、Mock 数据 |
| L2 增强能力 | 一期可演示，后续逐步工程化 | 数字孪生、客群画像、热力动线、历史回放 |
| L3 生产能力 | 真实上线前必须补齐 | 鉴权审计、后端 API、数据库、AI 视频服务、部署观测 |
| L4 远期能力 | 不纳入第一轮验收 | 招商推荐、多租户 SaaS、高精 BIM、跨商场经营优化 |

## 3. 业务对象

| 对象 | 说明 | 关键字段示例 |
| --- | --- | --- |
| 商场 | 系统管理的运营主体 | 商场 ID、名称、营业时间 |
| 楼层 | 空间分析单元 | 楼层 ID、名称、面积、拥挤阈值 |
| 店铺 | 经营分析单元 | 店铺 ID、业态、面积、楼层、状态 |
| 摄像头 | 视觉数据来源 | 摄像头 ID、楼层、安装区域、状态 |
| ROI | 进店、停留、热力等识别区域 | ROI ID、类型、几何区域 |
| 线段 | 进出方向判定边界 | 线段 ID、方向、关联店铺 |
| 事件 | 统计事实来源 | 事件 ID、时间、类型、来源、幂等键 |
| 统计指标 | 面向运营的聚合结果 | 客流、停留、转化、评分、告警 |
| 告警 | 需要处理的异常或低效状态 | 告警级别、规则、状态、责任角色 |

## 4. 功能需求

### 4.1 运营总览

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-OV-01 | 展示当前场内人数、今日累计客流、客流峰值、拥挤楼层 | L1 | 指标口径清晰，支持空态和异常态 |
| FR-OV-02 | 展示分时客流趋势和楼层对比 | L1 | 能看出时间变化和楼层差异 |
| FR-OV-03 | 支持从总览跳转到楼层或店铺详情 | L2 | 路由和上下文参数明确 |

### 4.2 店铺分析

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-ST-01 | 展示店铺进店人数、停留时长、转化率、评分和趋势 | L1 | 评分来源可解释 |
| FR-ST-02 | 支持业态、楼层、评分区间筛选 | L1 | 筛选状态可复现 |
| FR-ST-03 | 展示低效原因，如高客流低转化、停留不足、连续下滑 | L1 | 原因与指标规则一致 |

### 4.3 低效预警

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-AL-01 | 生成低评分、低转化、异常拥挤、数据异常预警 | L1 | 每类预警有规则和阈值 |
| FR-AL-02 | 支持预警等级、状态和处理建议 | L2 | 状态流转可审计 |
| FR-AL-03 | 支持按楼层、业态、等级筛选 | L2 | 筛选结果稳定 |

### 4.4 数字孪生与热力

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-DT-01 | 展示自绘楼层、店铺区域、热力和告警标记 | L2 | 不使用真实未授权平面图 |
| FR-DT-02 | 支持楼层切换、店铺点击、历史时间切换 | L2 | 交互状态清晰 |
| FR-DT-03 | 支持简化 2.5D 或 3D 场景 | L2 | 首屏可演示，性能可接受 |

### 4.5 客群画像

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-CP-01 | 展示匿名聚合的时段、楼层和业态偏好 | L2 | 不展示个人身份和个人轨迹 |
| FR-CP-02 | 展示活动前后或时间段对比 | L3 | 对比口径一致 |

### 4.6 权限与审计

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-AU-01 | 支持管理员、运营、招商、安保、只读角色 | L3 | 权限边界可测试 |
| FR-AU-02 | 记录关键配置、告警处理和登录操作 | L3 | 操作日志不可绕过 |

## 5. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 可用性 | 核心页面必须有加载、空态、错误、权限不足状态 |
| 性能 | 前端 Demo 大屏首屏目标小于 5 秒；后端 API 后续定义 P95 目标 |
| 可测试 | 需求、指标、规则、API、前端交互都要有对应测试或检查 |
| 可恢复 | 任意 AI 会话必须能从 `context/` 和 `PROGRESS.md` 继续 |
| 可审计 | 指标、事件、AI 输出、规则和操作都要保留来源和版本 |
| 隐私 | 只展示匿名聚合数据，不存储人脸原图，不展示个人轨迹 |
| 许可证 | 新依赖、素材、模型、字体、数据集必须先记录许可证 |
| 成本 | 默认本地免费开源方案，不接入付费服务 |

## 6. 约束与假设

| 类型 | 内容 |
| --- | --- |
| 数据假设 | 第一轮使用 Mock、合成或自绘数据 |
| 空间假设 | 楼层和店铺图形使用自绘几何，不还原真实商场 |
| AI 假设 | P0 只定义事件输出和审计要求，不选择具体模型权重 |
| 部署假设 | 优先 Docker Compose，本地可运行；不绑定云服务 |
| 合规假设 | 真实上线必须另行取得授权和合规确认 |
