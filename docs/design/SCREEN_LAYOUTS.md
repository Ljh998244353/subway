# 信息架构与页面范围

更新时间：2026-05-10

## 1. 文档定位

本文是 `P1-I1 information architecture and page scope` 的设计输出，用于把 P0 的需求、指标和系统设计转成前端页面范围。本文只定义页面、导航、核心区域、状态和跳转关系，不创建 `frontend/`、`backend/`、`ai-services/` 或 `infra/` 工程。

后续 P1-I2 到 P1-I4 会继续补充设计 token、布局规则、组件规范、图表规范、交互、响应式和可访问性检查。P2 才开始 React + TypeScript + Vite 前端工程。

## 2. 设计目标

第一轮前端 Demo 应表现为运营工作台，而不是营销展示页。

| 目标 | 设计要求 |
| --- | --- |
| 快速定位问题 | 首屏直接展示客流、拥挤、低效店铺和告警，不使用大篇幅介绍文案 |
| 指标可解释 | 每个指标区域标出统计口径、时间窗口和异常原因入口 |
| 空间可理解 | 数字孪生页使用自绘楼层几何、虚构店铺和合成热力 |
| 决策可追踪 | 店铺评分、低效原因、告警等级和处理状态在页面之间保持一致 |
| 合规可控 | 不使用真实商场图、真实品牌、商户 Logo、监控画面或人物图像 |
| 可测试可降级 | 所有核心页面都有加载、空态、错误、权限不足状态 |

## 3. 信息架构总览

一期包含 5 个核心业务页面和 1 组后续管理入口占位。管理入口在 P2 Demo 中可先隐藏或只作为禁用导航，不纳入本轮实现范围。

```text
App Shell
  顶部栏：商场选择、时间范围、数据模式、刷新状态、用户入口
  侧边导航：
    运营总览 /dashboard
    数字孪生 /digital-twin
    店铺分析 /store-analysis
    客群画像 /customer-profile
    低效预警 /store-alerts
    系统管理 /admin       P4/P10 后续占位
```

### 3.1 核心路由

| 路由 | 页面 | 主要用户 | 优先级 | P2 Demo 范围 |
| --- | --- | --- | --- | --- |
| `/dashboard` | 运营总览 | 运营经理、楼层主管、安保 | L1 | 必做 |
| `/digital-twin` | 数字孪生 | 运营经理、楼层主管、安保 | L2 | 必做简化版 |
| `/store-analysis` | 店铺分析 | 招商/租赁负责人、运营经理 | L1 | 必做 |
| `/customer-profile` | 客群画像 | 市场营销、运营经理 | L2 | 必做聚合版 |
| `/store-alerts` | 低效预警 | 运营经理、招商、安保 | L1 | 必做 |
| `/admin` | 系统管理 | 管理员 | L3 | 后续占位 |

### 3.2 全局筛选

| 控件 | 位置 | 作用 | 默认值 |
| --- | --- | --- | --- |
| 商场选择 | 顶部栏左侧 | 后续支持多商场；P2 仅单商场 Mock | `示范商业中心` |
| 时间范围 | 顶部栏中部 | 影响趋势、排行、画像和告警 | `今日` |
| 楼层选择 | 页面内或顶部辅助筛选 | 影响楼层、店铺和热力 | `全部楼层` |
| 数据模式 | 顶部栏右侧 | 标识 Mock / API / 离线回放 | P2 为 `Mock` |
| 刷新状态 | 顶部栏右侧 | 显示最近更新时间和数据延迟 | `刚刚更新` |

全局筛选应通过 URL query 或可恢复的前端状态保存，避免页面跳转后丢失上下文。P2 可先用前端 Mock 状态实现，P5 接 API 后再与后端参数对齐。

## 4. 页面跳转关系

```text
/dashboard
  点击拥挤楼层 -> /digital-twin?floorId=F2&mode=heatmap
  点击低效店铺 -> /store-analysis?storeId=S102
  点击告警卡片 -> /store-alerts?alertId=A9001

/digital-twin
  点击店铺区域 -> /store-analysis?storeId=S102&from=twin
  点击告警标记 -> /store-alerts?alertId=A9001&floorId=F2
  切换历史时间 -> 保持当前路由，更新 timeRange

/store-analysis
  点击低效原因 -> /store-alerts?storeId=S102
  点击空间位置 -> /digital-twin?storeId=S102&floorId=F2
  点击业态对比 -> 保持当前路由，切换 category filter

/customer-profile
  点击楼层偏好 -> /digital-twin?floorId=F2&mode=flow
  点击业态偏好 -> /store-analysis?category=餐饮

/store-alerts
  点击告警对象 -> /store-analysis?storeId=S102 或 /digital-twin?floorId=F2
  点击处理状态 -> 保持当前路由，打开处理面板
```

所有跳转必须保留 `mallId`、`timeRange` 和必要筛选条件。没有权限时跳转到目标页面的权限不足状态，而不是静默失败。

## 6. 核心页面范围

### 6.1 运营总览 `/dashboard`

页面目标：让运营经理在 30 秒内判断当前商场是否正常、哪里拥挤、哪些店铺需要优先关注。

| 区域 | 内容 | 指标或数据 |
| --- | --- | --- |
| KPI 条 | 当前场内人数、今日累计客流、峰值客流、拥挤指数、未处理告警 | `currentOccupancy`、`todayTraffic`、`peakTraffic`、`crowdingIndex`、`openAlerts` |
| 客流趋势 | 今日分时曲线、同比/环比占位、峰值标记 | 5 分钟或小时粒度 |
| 楼层状态 | 楼层客流、拥挤指数、异常数量、热力摘要 | 楼层维度聚合 |
| 低效店铺榜 | C/D 级店铺、评分、低效原因、楼层 | 店铺评分和告警 |
| 实时告警摘要 | 高等级告警、位置、持续时间、建议动作 | 告警状态 |

关键交互：

```text
点击楼层状态 -> 数字孪生并带 floorId
点击店铺榜 -> 店铺分析并带 storeId
点击告警摘要 -> 低效预警并带 alertId
切换时间范围 -> 所有趋势和榜单同步更新
```

P2 Demo 非目标：

```text
不做真实实时推送
不做复杂自定义报表
不做真实导出
```

### 6.2 数字孪生 `/digital-twin`

页面目标：用空间视图解释楼层、店铺、热力和告警之间的关系，帮助定位问题区域。

| 区域 | 内容 | 指标或数据 |
| --- | --- | --- |
| 楼层切换 | F1/F2/F3 等虚构楼层 | `floorId` |
| 模式切换 | 热力、客流、告警、评分 | `mode` |
| 自绘楼层画布 | 几何店铺块、通道、入口、节点 | 自绘坐标，不还原真实商场 |
| 覆盖层 | 热力点、流向线、告警标记、评分色阶 | 合成数据 |
| 选中详情 | 店铺名称、业态、客流、转化、评分、告警 | 店铺详情摘要 |
| 回放控制 | 当前时间点、播放/暂停占位 | P2 可做静态切换或简单 Mock |

关键交互：

```text
鼠标悬停店铺 -> 显示轻量 tooltip
点击店铺 -> 固定右侧详情
点击告警点 -> 展示告警说明和处理入口
切换楼层 -> 保持模式，刷新楼层图和指标
切换模式 -> 同一楼层切换不同覆盖层
```

设计约束：

```text
楼层图必须为自绘抽象几何
店铺名必须虚构
不使用真实商场平面图、BIM、地图瓦片、品牌 Logo 或监控截图
不展示个人级轨迹，只允许聚合流向或热力
```

P2 Demo 非目标：

```text
不做高精 BIM
不接 Three.js 复杂模型
不使用外部地图服务
```

### 6.3 店铺分析 `/store-analysis`

页面目标：解释店铺表现和低效原因，让招商或运营人员能按楼层、业态和评分快速筛选。

| 区域 | 内容 | 指标或数据 |
| --- | --- | --- |
| 筛选栏 | 楼层、业态、评分等级、时间范围、关键词 | URL 可恢复 |
| 店铺列表 | 店铺名、楼层、业态、评分、等级、趋势、告警数 | 店铺排名 |
| 店铺详情 | 进店、曝光、转化、停留、店内人数、评分拆解 | 店铺指标 |
| 趋势图 | 进店、转化、停留、评分随时间变化 | 小时/日粒度 |
| 低效解释 | 高客流低转化、停留不足、连续下滑、数据异常 | 告警规则 |
| 空间入口 | 查看所在楼层位置 | 跳转数字孪生 |

关键交互：

```text
选择店铺列表项 -> 更新详情面板
点击评分等级 -> 筛选 A/B/C/D 店铺
点击低效原因 -> 跳转低效预警并带 storeId
点击空间位置 -> 跳转数字孪生并高亮店铺
```

P2 Demo 非目标：

```text
不实现真实编辑店铺资料
不实现招商合同或租金分析
不实现复杂推荐算法
```

### 6.4 客群画像 `/customer-profile`

页面目标：展示匿名聚合的时间、楼层和业态偏好，服务活动评估和运营分析。

| 区域 | 内容 | 指标或数据 |
| --- | --- | --- |
| 概览指标 | 活跃时段、主要楼层、热门业态、回访倾向占位 | 聚合统计 |
| 时段分布 | 分时客流柱状图或热力矩阵 | 时间窗口 |
| 楼层偏好 | 楼层客流占比、停留占比 | 楼层聚合 |
| 业态偏好 | 餐饮、零售、娱乐、服务等虚构业态占比 | 业态聚合 |
| 活动对比 | 活动前后客流变化占位 | P2 可用 Mock 对比 |
| 说明区 | 隐私边界和口径说明 | 匿名聚合，不展示个人 |

关键交互：

```text
点击楼层偏好 -> 数字孪生并带 floorId
点击业态偏好 -> 店铺分析并带 category
切换时间范围 -> 所有画像聚合重新计算
```

隐私约束：

```text
不出现人脸、年龄性别识别、身份标签、手机号、会员 ID 或个人轨迹
不提供单人路径回放
不展示能反推个人身份的小样本明细
```

P2 Demo 非目标：

```text
不做人群身份识别
不做人脸属性识别
不做个人级营销触达
```

### 6.5 低效预警 `/store-alerts`

页面目标：集中展示需要处理的店铺和区域异常，并提供可解释的优先级和处理状态。

| 区域 | 内容 | 指标或数据 |
| --- | --- | --- |
| 预警 KPI | 未处理、高等级、今日新增、平均持续时间 | 告警统计 |
| 筛选栏 | 等级、状态、楼层、业态、规则类型、时间范围 | URL 可恢复 |
| 告警列表 | 标题、对象、等级、规则、持续时间、状态、建议动作 | 告警明细 |
| 告警详情 | 触发指标、阈值、趋势、关联店铺、处理记录 | 告警解释 |
| 空间定位 | 查看楼层位置、店铺详情 | 跳转数字孪生或店铺分析 |
| 处理面板 | 状态切换、备注、负责人占位 | P2 可 Mock，不写后端 |

关键交互：

```text
点击告警 -> 展示详情
点击对象 -> 店铺分析或数字孪生
切换状态 -> P2 仅前端 Mock 更新
按等级筛选 -> 列表和 KPI 同步变化
```

P2 Demo 非目标：

```text
不实现真实工单系统
不写入真实审计日志
不发送短信、邮件或外部通知
```

## 7. 页面状态规范

每个核心页面都必须覆盖以下状态。P2 实现时应把状态纳入组件测试或 E2E 检查。

| 状态 | 触发 | 页面表现 | 用户动作 |
| --- | --- | --- | --- |
| Loading | 首次进入、筛选变化、刷新 | 保留页面骨架，指标和图表显示 skeleton | 等待或取消筛选 |
| Empty | 当前筛选无数据 | 显示空态说明、当前筛选摘要、重置筛选按钮 | 重置筛选 |
| Error | Mock/API 读取失败或数据格式异常 | 显示错误摘要、重试按钮、降级到最近可用数据占位 | 重试或切换时间 |
| Permission Denied | 角色无权查看页面或对象 | 显示权限不足、当前角色、需要的权限 | 返回总览 |
| Partial Data | 部分指标缺失或延迟 | 指标卡标记数据延迟，图表显示缺口 | 查看口径说明 |
| Stale Data | 数据超过刷新阈值 | 顶部栏和相关指标显示延迟提示 | 手动刷新 |

状态文案必须简短，不能把功能说明写成大段教程。错误和权限状态需要可测试的标识，便于后续 Playwright 定位。

## 8. 页面级权限草案

P2 可以使用静态角色模拟；P4/P10 再接真实 RBAC。

| 页面 | admin | operator | leasing | security | readonly |
| --- | --- | --- | --- | --- | --- |
| 运营总览 | 可读写 | 可读 | 可读 | 可读 | 可读 |
| 数字孪生 | 可读写 | 可读 | 可读 | 可读 | 可读 |
| 店铺分析 | 可读写 | 可读 | 可读写备注占位 | 只读部分 | 可读 |
| 客群画像 | 可读写 | 可读 | 可读 | 不可见或只读摘要 | 可读 |
| 低效预警 | 可读写 | 可处理 | 可读和备注占位 | 可处理拥挤类 | 可读 |
| 系统管理 | 可读写 | 不可见 | 不可见 | 不可见 | 不可见 |

## 9. Mock 数据范围

P2 Mock 数据必须覆盖：

| 数据集 | 最小规模 | 用途 |
| --- | --- | --- |
| mall | 1 个虚构商场 | 全局上下文 |
| floor | 3 到 5 个虚构楼层 | 楼层筛选和数字孪生 |
| store | 24 到 60 个虚构店铺 | 店铺列表、评分、楼层图 |
| traffic series | 今日分时和近 7 日 | 总览趋势 |
| heatmap points | 每楼层 30 到 80 个合成点 | 数字孪生热力 |
| flow edges | 每楼层 5 到 12 条聚合流向 | 数字孪生动线 |
| store scores | 覆盖 A/B/C/D 等级 | 店铺分析和预警 |
| alerts | 覆盖高/中/低、未处理/处理中/已关闭 | 低效预警 |
| customer profile | 时段、楼层、业态聚合 | 客群画像 |

Mock 数据不得使用真实商场名称、真实品牌名、商户 Logo、真实地图坐标或可识别个人信息。

## 10. 设计素材策略

| 类型 | 当前策略 | 许可证处理 |
| --- | --- | --- |
| 楼层图 | 自绘几何矩形、通道、节点和入口 | 项目自有，不需要第三方声明 |
| 店铺名称 | 虚构名称或通用业态名 | 不使用真实品牌 |
| 图标 | P2 选定许可证清晰的开源图标库 | 选型后记录第三方声明和许可证审计 |
| 字体 | 优先系统字体或已记录字体 | 新增字体必须审计 |
| 图片/视频 | P2 不使用外部图片或视频素材 | 如后续新增必须先审计 |
| 数据 | 合成 Mock 数据 | 标记为 synthetic/mock |
| 色彩 | P1-I2 定义设计 token | 不从未授权设计稿复制 |

## 11. P2 页面实现顺序建议

```text
P2-I1 frontend project initialization
P2-I2 mock data and shared types
P2-I3 operations overview dashboard
P2-I4 store analysis page
P2-I5 store alerts page
P2-I6 digital twin demo page
```
